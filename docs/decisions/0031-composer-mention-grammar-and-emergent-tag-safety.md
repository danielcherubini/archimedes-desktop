# The composer mention grammar (`$` / `#` / `@`), the hard/soft split, and emergent tag safety

The composer could already name a **Skill** (`$name`, ZCode parity). Naming an **Agent definition** or an **MCP server** needed the same affordance, so we settled ONE grammar for all three: `$` → Skill, `@` → Agent definition, `#` → MCP server, all sharing the token shape `[a-z0-9]+(?:-[a-z0-9]+)*`, lowercase-only tokens, case-insensitive matching on the resource-name side, and an UNMATCHED token left verbatim. Two things were decided deliberately and are easy to "helpfully" undo later, so they are recorded here.

**1. The left boundary is ASYMMETRIC.** `$` keeps its boundary-free-left form (a bare `$` mid-word still matches) because that is pi/ZCode's exact behavior and changing it changes documented behavior. `#` and `@` REQUIRE a leading whitespace or line-start (`(^|\s)`), because `#` and `@` are high-frequency in the text a coding user pastes — `#[derive]`, `# Title`, `C#`, `user@example.com`, `git@github.com` must never be mentions. `#include` / `#123` / `#hashtag` DO match the token grammar, so **catalog-gating is load-bearing**: a token expands only if a resource with that exact name exists. Consequence of the consumed boundary: `@a@b` expands only `@a` (pinned — the second token has no whitespace left to satisfy its boundary).

**2. `$` is a HARD trigger; `@` and `#` are SOFT pointers.** `$name` injects the skill's full body — the injected text IS the task. An agent definition or an MCP server, by contrast, is reached through an **agent-initiated tool call** (`subagent`'s `agentName`; the `mcp` tool's connect/list/call), so a mention cannot BE the dispatch. `@`/`#` therefore inject a short *hint* naming the resource (name + one-line description / server summary) and the agent decides to act — the UI copy says "named by the user", never "loaded". Two sub-consequences: the picker's `@` catalog is the **user + space-level** set (widened by a new `list_agent_definitions_for_space` command to match exactly what `agentName` dispatch honors — the Settings command stays user-level-only and byte-identical), and the `#` catalog is the **effective three-layer merge** (`list_mcp_servers_effective`, ADR 0019 precedence) rather than the desktop's own entries — ADR 0019's "Settings shows only desktop entries" decision STANDS, because the mention picker is not the Settings surface.

**3. Tag safety of the interpolated name is EMERGENT, not checked — and that is the load-bearing invariant.** Each expansion interpolates the catalog resource's VERBATIM name into a prompt tag three times (`<agent name="X">`, `"X"`, `agentName "X"`; likewise `<mcp …>`, `connect: "X"`). Nothing validates those names: Skills are guarded at discovery (`skills.rs::is_tag_safe_name`), but Agent names deliberately are NOT (ADR 0020) and MCP server names are raw JSON object keys. What makes injection impossible is the LOOKUP: a hit requires `name.toLowerCase() === token`, and a token is `[a-z0-9-]+` — so any matched name is necessarily tag-safe. Note the argument must be stated this way, NOT as "lowercasing is injective over the alphabet" (it is not: `"K".toLowerCase() === "k"` — U+212A is tag-SAFE, so it is a counterexample to injectivity and to nothing else). **If matching ever becomes prefix/fuzzy/looser-folding, this argument collapses and the names must be validated or escaped instead** — `skills.test.ts`'s tag-safety block is the tripwire.

**Considered Options**

- **`@`/`#` as hard triggers** (inject the full agent frontmatter + body / eagerly connect the server and inject its tool names): rejected — the tool call is the agent's to make, and the server's tool list exists only per **Worker** session (`McpManager` is per-`AgentLoop`, ADR 0018/0019), so it is unknowable to the Client at send time. A tool-level `#` picker would need a Supervisor→Worker round-trip and a wider token charset (real tool names carry `_` and `.`, which this grammar truncates at) — deferred, not rejected in principle.
- **Require the word boundary on `$` too** (one symmetric grammar): rejected — it changes ZCode-parity `$` behavior that users and tests already depend on.
- **Skip non-tag-safe names in `discover_agents`** (mirror the Skills guard): rejected — it would break `agentName` dispatch for existing user files (a name containing a space is dispatchable by the model verbatim), and `list_agents` output is JSON-escaped anyway. The filter belongs at the MENTION-PICKER boundary instead, where it prevents a DEAD token (a picked row whose token can never expand): `is_mentionable_name` (strictly stronger than `is_tag_safe_name`, which admits a space) gates `server_infos` and `list_agent_definitions_for_space` only.
- **Escape the interpolated name** (HTML-attribute-style): rejected — provably unreachable given exact matching; escaping code that cannot be exercised decays into a false sense of safety.
- **Cap only the Agent `description`**: rejected mid-review — the `description` AND the MCP `summary` are BOTH repo-controlled (`<cwd>/.pi/mcp.json` and `.agents/agents/*.md` come from a cloned repo), so both are capped at 1024 CODE POINTS at the injection point (`capInterpolated`); an uncapped `args` array in a hostile `.pi/mcp.json` was a real prompt-flood vector reaching both the prompt and the persisted message.

**Consequences**

- **Two new read-only IPC commands** (`list_agent_definitions_for_space`, `list_mcp_servers_effective`) — config reads only; the per-session `McpManager` and the "never connect from the Client" rule are untouched. `is_tag_safe_name` became `pub(crate)` (shared, not mirrored — the ADR 0020 "keep the modules independent" rule is scoped to `parse_value`).
- **The persisted text IS the expanded text.** Expansion happens in `send()` before both `addUserMessage` and `sendPrompt`, so the live bubble, the stored row, and the model's input are byte-identical and `mergeDedupeKey` matches across a resume; `splitMentionBlocks` is display-only and degrades the WHOLE message to verbatim on any shape disagreement (a hostile `</agent>` inside a description truncates the parse and renders as plain text — no data loss, no display corruption).
- **A resource whose name is not mentionable is invisible to `@`/`#` by design** (unnameable: names with spaces, dots, `_`, or `a--b`). This is the safe direction of the picker-vs-expansion divergence; the one character pair that diverges for real (U+212A) hides rather than over-offers.
- **The `$`-only trio (`expandSkillMentions` / `splitSkillBlocks` / `activeSkillToken`) has no production caller and is NOT dead code** — it is the retained differential ORACLE pinning byte-identical `$` behavior; retiring one means retiring its generalized counterpart in the same change.
- **Code fences are not exempt**: `` @agent `` inside a fenced block expands (inline `` `@agent` `` does not — the backtick fails the boundary). Accepted: the token is a user-authored trigger, and the user wrote the fence.
