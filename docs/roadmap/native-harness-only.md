# Native harness only — rip out the pi harness integration — Plan

**Goal:** Remove the desktop's entire first-generation pi integration (external sessions, the bridge socket channel, the agent registry, the pi-config seeding) so the desktop is only the native archimedes harness: one harness, one model source (the Settings providers list), one config surface (`settings.json`).

**Architecture:** The native in-process `AgentLoop` (`src-tauri/src/agent/harness/`) is the only Agent harness. The four mixed files (`session.rs` / `bridge.rs` / `subagent.rs` / `permission.rs`) are split so the native code stands alone; the in-process interactive cores (ask/sudo/todo) move to a new `agent/interactive.rs` and the `bridge-*` wire events are renamed `interactive-*`; the agent registry, `agents.json`, and `seed_from_pi_config` are deleted (the `HarnessConfig` fields move into `settings.json`); a one-way DB migration deletes ALL external `sessions` rows (their `messages` rows cascade) and drops `sessions.agent_id` — the `messages` table STAYS (it is the display transcript for native sessions too; `native_messages` is a different table, the provider transcript for resume).

**Tech Stack:** Rust (Tauri 2 backend, `src-tauri/`), tokio, rusqlite, serde; React 19 + TypeScript frontend (`src/`). No new dependencies (the `windows` crate is REMOVED in Task 2).

**Conventions (all tasks):** Rust validation from `src-tauri/`: `cargo test`, `cargo clippy --all-targets` (must be 0 warnings), `cargo fmt --check`. Frontend validation from the repo root: `pnpm test`, `pnpm build`. TDD: update/write the failing test first, confirm it fails, then implement. Each task is independently commitable and leaves the branch green.

**Reference spec:** the approved design is in git history (commit `b0e5f64`, `docs: add native-harness-only spec + ADR 0022`) — this plan replaces it in the same file. ADR 0022 (already committed, amended in this commit for the two reviewer corrections — the `messages`-table retention and the `NativeDeps` catalog fix) records the decision; the docs task below performs the ADR deletions + CONTEXT.md rewrites it describes.

**What NOT to change (all tasks):** `src-tauri/src/agent/harness/` (the native `AgentLoop`/`Provider`/`compact`/`prompt`/`retry`/`store` — the ONLY edits inside `harness/` are: the `catalog.rs` seed removal in Task 1, the `RpcEvent` import-path update in `harness/loop.rs` + `harness/retry.rs` in Task 1 (`crate::agent::rpc` → `crate::agent::events` — no behavior change), and the `SessionInfo` test literal at `harness/loop.rs:2284` in Task 1 (drop the `agent_id` field — the struct loses the field; the literal must be updated or the crate will not compile), `src-tauri/src/agent/mcp/` (the MCP module has its own `RpcError` struct in `mcp/rpc.rs` — a DIFFERENT type, same name; do not rename it), `src-tauri/src/agent/fs_backend.rs`, `src-tauri/src/agent/todo.rs`, `src-tauri/src/skills.rs`, `src-tauri/src/agents.rs` (the `~/.agents/` + `~/.pi/agent/` discovery roots are data locations — ADR 0022), `bin/fake_mcp_stdio.rs`, `tauri.conf.json`, the `native_messages` / `spaces` tables and their crash-recovery machinery in `storage/db.rs`, and the `messages` table (see Task 1 — it is the native display transcript).

### Task 1: The native-only core (external path + registry + seeding removal, DB migration)

**Context:**
The desktop has two session paths: EXTERNAL (a spawned `pi --mode rpc` process driven through `PiRpc` + the bridge socket) and NATIVE (the in-process `AgentLoop`, ADR 0011). This task makes the desktop native-only: it deletes the entire external path, the agent registry (with the built-in `pi` default entry + the `archimedes` native entry), and the pi-config seeding of the model catalog (`seed_from_pi_config`, ADR 0012 — ADR 0014 already scheduled its removal), rewires the native session start/resume to be settings-driven (the `HarnessConfig` fields move into `settings.json`), renames `RpcError` → `SessionError`, moves `RpcEvent` out of the deleted `rpc.rs`, and lands the one-way DB migration. The native path's BEHAVIOR is unchanged — this is a rip-out, not a feature. The native ask/sudo/todo machinery still lives in `bridge.rs` after this task (Task 2 extracts it). Two reviewer-verified subtleties drive the shape: (1) the `messages` table is the DISPLAY transcript for native sessions too (the native `AgentLoop::emit` → `normalize` + `persist_update` → `db.record_message`; the frontend `load_history` hydrates stored sessions from it) — so the migration deletes external ROWS but keeps the TABLE; (2) `NativeDeps.catalog` is a startup snapshot of the base catalog (which becomes empty once seeding goes) — it becomes a dispatch-time effective-catalog supplier so Agent definitions' `model:` frontmatter keeps resolving.
